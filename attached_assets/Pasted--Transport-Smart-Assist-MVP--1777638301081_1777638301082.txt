نحتاج تطبيق ميزة Transport Smart-Assist كـ MVP بسيط داخل صفحة تنفيذ الصفقة، بدون بناء نظام ناقلين كامل الآن.

الهدف:
بعد تأكيد الدفع، لا يضيع المستخدم؛ نوجّهه مباشرة لخطوة النقل بخيارين واضحين:

1. رتّب النقل لي
2. لا أحتاج نقل

المطلوب تنفيذياً:

1. أضف قسم Transport Step أسفل قسم تأكيد الدفع مباشرة.

الحالة قبل تأكيد الدفع:

* يكون القسم ظاهر لكن disabled أو muted.
* النص: "سيتم تفعيل خطوة النقل بعد تأكيد الدفع."

الحالة بعد تأكيد الدفع:

* يظهر عنوان: "الخطوة التالية: ترتيب النقل"
* يظهر نص مختصر:
  "هل تحتاج مساعدة في نقل المواد؟ يمكن لتدويرة مساعدتك في تنسيق طلب النقل."
* زران واضحان:

  * زر أساسي: "رتّب النقل لي"
  * زر ثانوي: "لا أحتاج نقل"

2. عند الضغط على "رتّب النقل لي":

* أنشئ Transport Request مرتبط بالصفقة/deal.
* خزّن البيانات التالية:

  * deal_id
  * listing_id
  * producer_company_id
  * buyer_company_id
  * pickup_city إن وجدت
  * delivery_city إن وجدت
  * material/category
  * quantity
  * status = requested
  * requested_by_company_id
  * created_at

3. بعد إنشاء الطلب:

* أظهر رسالة نجاح:
  "تم إنشاء طلب النقل. سيتواصل معك فريق تدويرة أو أحد الناقلين المناسبين."
* غيّر حالة قسم النقل إلى:
  "طلب النقل قيد التنسيق"
* لا تسمح بإنشاء أكثر من طلب نقل واحد لنفس الصفقة.

4. عند الضغط على "لا أحتاج نقل":

* خزّن transport_required = false أو transport_decision = not_required على الصفقة.
* أظهر رسالة:
  "تم تسجيل أن الصفقة لا تحتاج إلى خدمة نقل."
* لا تُظهر زر إنشاء طلب النقل بعدها إلا إذا قررنا لاحقاً إضافة تعديل القرار.

5. في حالة وجود طلب نقل سابق:

* لا تعرض زر "رتّب النقل لي".
* اعرض حالة الطلب:

  * requested: "طلب النقل قيد التنسيق"
  * assigned: "تم تعيين ناقل"
  * in_progress: "النقل جارٍ"
  * completed: "تم إكمال النقل"
  * cancelled: "تم إلغاء طلب النقل"

6. لا تبني حالياً:

* تسعير نقل تلقائي
* خرائط
* تتبع مباشر
* اختيار ناقل من قائمة
* لوحة ناقلين كاملة

7. أضف API endpoints بسيطة:

* POST /api/deals/:dealId/transport-request
* PATCH /api/deals/:dealId/transport-decision

8. أضف validation:

* لا يمكن إنشاء طلب نقل إلا بعد payment_confirmed.
* لا يمكن إنشاء طلب نقل إذا كانت الصفقة مكتملة أو ملغاة.
* لا يمكن إنشاء طلب مكرر لنفس deal_id.
* فقط أحد أطراف الصفقة يستطيع إنشاء القرار/الطلب.

9. UI:

* اجعل زر "رتّب النقل لي" واضح وكبير Full-width أو شبه Full-width مع أيقونة شاحنة.
* اجعل "لا أحتاج نقل" زر ثانوي.
* لا تجعل القسم صغيراً أو مخفياً.
* الهدف أن يشعر المستخدم أن النقل خطوة طبيعية بعد الدفع.

10. بعد التنفيذ:

* شغّل TypeScript check للـ frontend والـ backend.
* أرسل تقرير مختصر:

  * الملفات المعدلة
  * الجداول/الحقول الجديدة
  * الـ endpoints الجديدة
  * أي ملاحظات أو تعارضات
  * Screenshot للحالة قبل وبعد تأكيد الدفع
