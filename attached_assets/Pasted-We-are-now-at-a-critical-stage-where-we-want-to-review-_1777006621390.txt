## 3) Areas to review

---

### A) Marketplace Listing Experience

Goal:
A buyer should decide within 3 seconds whether to open a listing.

Required improvements:

* Clear listing summary card that shows:

  * Material (main + subcategory)
  * Form and condition (future-ready)
  * Location (city at minimum)
  * Price (unit + total)
  * Sales type (auction / direct / private)
  * Visual badges:

    * Participating or not
    * Highest bidder or not
    * Action required

* Image handling:

  * Small thumbnail in marketplace
  * Larger images inside listing details

---

### B) Self-Bidding Prevention

Problem:
User can bid against themselves without warning.

Expected:
If user is currently the highest bidder:

* Show clear warning before allowing a higher bid

---

### C) Error Messages

Problem:
Error messages are not aligned with actual issues.

Expected:
We want to:

* Extract all current system errors
* Map:

  * Error cause
  * Current message
  * Improved user-facing message
* Redesign all error messages in one pass

---

### D) Payment Confirmation Stage

Changes required:

* Rename stage to:
  "Confirm Receipt of Payment"

* Add:

  * Transfer reference number
  * Optional or required proof (image upload)

* Confirmation message:
  "You are confirming that you have received the payment from the buyer. This action cannot be reversed."

---

### E) Governance & Terms

We will introduce:

* Terms and conditions covering:

  * Seller responsibility in choosing offers
  * Accepting lower offers
  * Payment confirmation responsibility
  * Platform liability boundaries
  * Role-based responsibility within companies

* Must be:

  * Accepted during registration
  * Accessible as a standalone page

---

### F) Company Structure (Multi-User)

Requirement:

* One company can have multiple users

Roles:

* Admin
* Operator
* Viewer

Capabilities:

* Admin approves users and manages roles
* Alerts for abnormal decisions (e.g. accepting lower offer)

This is also tied to future monetization (subscriptions based on users and roles)

---

### G) Material Classification

We want a flexible classification system:

* Main category + subcategory
* Managed fully from Admin (no hardcoding)

"Other":

* Must exist
* Requires mandatory description
* Used for future classification improvements

---
