## Core Rules

1) Deal creation (MANDATORY)
- Auto-create a deal record inside the SAME DB transaction of POST /offers/:id/accept
- Enforce 1:1 (UNIQUE on offer_id)
- Must NOT alter existing acceptance logic or side-effects

2) Settlement (derived, not user-entered)
- Derive from existing data:
  - fixed → final_amount = estimated_amount (immutable at creation)
  - by_weight → producer must enter actual_quantity during confirm-payment
- Do NOT introduce a new user input for settlement_type

3) Transitions (role-based, guarded, idempotent)

- POST /deals/:id/confirm-payment  (producer)
  - If by_weight: require actual_quantity
  - Compute & set final_amount
  - Set payment_confirmed_at + payment_confirmed_by
  - Status → payment_confirmed
  - Lock actual_quantity and final_amount (immutable afterwards)

- POST /deals/:id/confirm-dispatch  (producer)
  - Set dispatched_at + dispatched_by
  - Status → dispatched

- POST /deals/:id/confirm-receipt  (buyer)
  - Set received_at + received_by
  - Status → completed

4) Contact disclosure (MUST)
- After acceptance only:
  - producer sees buyer phone
  - buyer sees producer phone
- Read-only; sourced from companies profile

5) Constraints
- No payment proof upload
- No carrier fields
- No changes to M4.5 APIs or DB
- Enforce transitions via:
  - status guards
  - SELECT FOR UPDATE (row-level lock)
  - idempotency (repeat calls → 409, no mutation)
