We want to implement a focused MVP Transporter Portal + Transport Quotation Flow for Tadweerah.

This feature is strategically important because Tadweerah should not only help users request transport, but also help Admin/Ops compare transporter quotes and gradually prepare transport request data for future MWAN/eManifest readiness.

Please read this carefully before implementation.

==================================================
Business Goal
==================================================

When a buyer/seller chooses:
"رتّبوا لي النقل عبر تدويرة"

Tadweerah should create a transport request that can be:

1) Seen by Tadweerah Admin/Ops
2) Seen by qualified transporter companies
3) Quoted by transporters
4) Compared by Admin/Ops
5) Used to enrich eManifest-ready transport data

The goal is NOT to build a full transport marketplace now.

The goal is to build a simple, safe, additive MVP flow:

Transport Request → Transporter Quotes → Admin Comparison → Manual Admin Follow-up

This should help Tadweerah move closer to a future model where most MWAN/eManifest data is already collected inside Tadweerah, reducing duplicate data entry later.

==================================================
Critical Constraints
==================================================

Do not change deal lifecycle.
Do not change transport request state machine unless absolutely required and approved.
Do not change VAT, offers, pricing, reports, company approval, or admin auth.
Do not implement payment for transport.
Do not implement auto-award.
Do not implement transporter ratings.
Do not implement notifications.
Do not integrate with MWAN.
Do not call MWAN APIs.
Do not create official eManifest records.
Do not build PDF or formal transport invoices.
Do not expose deal financial values to transporters.
Do not expose buyer/seller sensitive commercial data unless needed for transport pricing.

This must be additive and isolated.

==================================================
Approved MVP Scope
==================================================

1) Transporter Portal / Page
2) Transport Quote Submission
3) Admin Quote Comparison
4) eManifest Readiness data display/enrichment
5) No automatic assignment or lifecycle automation

2) Transport Quote Submission
==================================================

Transporter can submit a quote for a transport request.

Create a new additive table if needed:

transport_quotes

Suggested fields:
- id uuid primary key
- transport_request_id uuid FK
- transporter_company_id uuid FK
- quote_amount numeric(12,2) not null
- currency text default 'SAR'
- estimated_pickup_date date nullable
- estimated_delivery_date date nullable
- truck_count integer nullable
- truck_type text nullable
- capacity_notes text nullable
- vehicle_plate text nullable
- driver_name text nullable
- notes text nullable
- validity_days integer nullable
- status text default 'submitted'
  allowed values:
  - submitted
  - under_review
  - selected
  - rejected
- created_at
- updated_at

Important:
- vehicle_plate and driver_name are optional for MVP.
- Do not require all eManifest-related fields to submit a quote.
- Minimum quote submission should require quote_amount only, plus optional supporting details.
- If a partial unique index is hard with the current ORM, enforce duplicate prevention in application logic first.

Duplicate rule:
One active non-rejected quote per transporter per transport request.

Transporter quote form fields:
- Quote amount
- Estimated pickup date
- Estimated delivery date
- Number of trucks
- Truck type
- Capacity notes
- Vehicle plate, optional
- Driver name, optional
- Notes
- Validity days

==================================================
3) Backend Routes
==================================================

Add routes safely and additively.

Transporter routes:

A) GET /api/transport-requests/available
Already exists according to assessment.
Extend it only if needed to include logistics-relevant fields.

It should return:
- request id/reference
- material/subcategory
- quantity/weight/unit
- pickup/delivery city
- pickup/delivery location details
- planned pickup date
- notes
- whether current transporter has already submitted a quote

Do not return deal financial values.

B) POST /api/transport-requests/:id/quotes
Guards:
- requireAuth
- requireCompany
- require transporter role/capability

Rules:
- transport request must be pending / available for quoting
- request should be platform/Tadweerah-assisted mode if such field exists
- transporter can submit only one active quote per request
- validate quote amount > 0
- do not change transport_request status
- do not assign transporter automatically

C) GET /api/transport-requests/:id/quotes/mine
Returns only the authenticated transporter company’s own quote(s) for that request.

Admin routes:

D) GET /api/admin/transport-requests/:id/quotes
Guard:
- requireAdminKey / X-Admin-Key

Returns all quotes for the transport request.

E) PATCH /api/admin/transport-quotes/:id/status
Guard:
- requireAdminKey / X-Admin-Key

Admin can set quote status:
- under_review
- selected
- rejected

Important:
Selecting a quote should only update the quote status.
Do not automatically change transport_request status.
Do not automatically assign transporter_company_id.
If assignment is easy and already supported, report first before implementing.

5) eManifest Readiness Alignment
==================================================

This is very important.

This feature should be designed so Tadweerah gradually collects data that can later help populate MWAN/eManifest fields.

Do not integrate with MWAN now.
Do not call MWAN APIs.
Do not create official eManifest records.
Do not build external submission.

This is data-readiness only.

The system should show an "eManifest Readiness" or "MWAN Readiness" section in Admin > Transport Requests, preferably near the quotes.

Arabic:
"جاهزية eManifest"

English:
"eManifest Readiness"

The readiness section should indicate which fields are available and which are missing.

Data that should already be derived from Tadweerah:
- Waste generator / producer company
- Receiving/buyer company
- Material category
- Material subcategory
- Waste/material description
- Quantity/weight/unit
- Pickup city
- Pickup location address
- Pickup Google Maps link
- Delivery city/location if available
- Planned pickup date if available
- Manifest reference if already available

Data that transporter quote can enrich:
- Transporter company
- Truck count
- Truck type
- Vehicle plate, optional
- Driver name, optional
- Estimated pickup date
- Estimated delivery date
- Capacity notes
- Transport notes
- Special handling requirements if any

Display readiness as:
- Completed fields
- Missing fields
- Fields provided by selected/submitted quote
- Fields still required before official MWAN/eManifest creation

Important:
- Do not block quote submission due to missing eManifest fields.
- Driver and vehicle details are optional for MVP.
- Admin can compare quotes and also see which quote provides more complete transport data.
- Do not change the transport request state machine.

7) Security and Privacy
==================================================

Transporter:
- Can see only available transport requests intended for quotation.
- Can submit quote only as their own company.
- Can see only their own quote(s).
- Cannot see other transporter quotes.
- Cannot see deal financial values.
- Cannot see buyer/seller commercial details unless absolutely necessary for transport pricing.

Admin:
- Can see all transport requests and all quotes.
- Must use existing ADMIN_API_KEY protection.

Buyer/Seller:
- Existing flows must remain unchanged.
- Buyer/seller should not see transporter quotes in this MVP unless explicitly already designed.
- Do not expose quotes in reports now.

Reports:
- Existing reports should remain untouched.
- Do not join transport_quotes into reports yet.

==================================================

==================================================

- Payment for transport
- Transporter rating
- Quote revisions/versioning
- Notifications
- MWAN API integration

- PDF/export for transport quotes
- Adding transport quote data to reports
