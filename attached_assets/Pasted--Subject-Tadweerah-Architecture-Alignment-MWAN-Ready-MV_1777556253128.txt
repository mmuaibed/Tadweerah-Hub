📩 Subject: Tadweerah Architecture Alignment – MWAN-Ready MVP with Production-Grade Foundation
🔷 1. Context (Why this matters now)

Following a deeper analysis of the National Center for Waste Management (MWAN) ecosystem, especially the eManifest system, we reached a critical conclusion:

MWAN is evolving into the national system of record for waste movement, compliance, and traceability.

Therefore:

Tadweerah must be built as a compatible digital layer, not a parallel or competing system.

🎯 2. Objective of this update

This update is NOT a redesign or feature expansion.

This is a targeted architectural alignment to ensure:

No future rework when integrating with MWAN
Minimal data duplication
High-quality platform experience from day one
Fast MVP delivery with a clear upgrade path
⚠️ 3. Key constraint (Non-negotiable)

The MVP must remain:

simple
fast to implement
low-cost (efficient queries, minimal complexity)

All changes must follow:

Refactor + Extend → NOT rebuild

🔷 4. Core Architecture Principles
4.1 Single Source of Truth (SSOT)

All core data must be:

created once → reused everywhere

Entities include:

companies
locations
waste definitions
vehicles
4.2 Multi-Role Entity Model (Mandatory)

Each company must support multiple roles simultaneously.

Roles (MVP scope):
roles: [
  "generator",
  "receiver",
  "transporter"
]
Real-world examples:
Scrap company → generator + receiver
Recycling facility → receiver + generator
Transport company → transporter
Integrated operator → all roles
4.3 Dynamic Dashboard (Modular UX)

One system, not multiple systems.

Requirement:
Single dashboard
Modules shown/hidden based on roles
Modules:
Generator:
Create Listing
My Waste
Outgoing Requests
Receiver:
Incoming Materials
Purchase Requests
Transporter:
Available Jobs
Active Trips
If multiple roles:

Modules are combined dynamically (no duplication)

4.4 Dynamic Classification System (Admin-Controlled)

All classifications must be database-driven.

Required tables:
service_activities
waste_categories
waste_subcategories
Admin capabilities:
add / edit / deactivate
no developer dependency

5.1 Conceptual Mapping

Waste Movement = Structured Transaction

all required data is complete for MWAN
